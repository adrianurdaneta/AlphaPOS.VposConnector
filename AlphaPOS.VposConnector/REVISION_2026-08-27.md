# Revisión de AlphaPOS.VposConnector

Fecha: 2026-08-27

## Alcance

Revisión del código, configuración, pruebas, documentación y cambios locales del proyecto. No se modificaron archivos existentes durante la revisión.

## Hallazgos

### Alto: ruptura de compatibilidad COM

`VposConnector.cs` conserva el mismo `GUID` y `ClassInterface(AutoDual)`, pero cambia contratos públicos:

- `VerificarP2C` pasa de tres argumentos a dos.
- `ObtenerMediosPago` pasa de retornar `int` a retornar `string`.

Los README y manuales anteriores documentaban la API anterior. Consumidores VFP ya desplegados pueden fallar por cantidad de argumentos o interpretar incorrectamente el retorno.

Recomendación: conservar los métodos legacy, agregar métodos nuevos o versionar explícitamente el contrato COM antes de distribuir la DLL.

### Alto: posible regresión en medios de pago

`VerificarP2C` y `PagarBiopago` ahora envían `accion: "tarjeta"`, `cedula` y `medioPago`. La implementación anterior enviaba `verificacionP2C` o `serviciosExternos` con otros campos.

No existen pruebas que validen estos payloads contra el contrato de VPOS. Se debe confirmar el contrato real del endpoint y agregar pruebas de solicitud.

### Alto: monto insertado directamente como JSON

En `VposConnector.cs:402-428`, el monto se concatena como texto sin validación ni serialización numérica. Valores con coma decimal, texto, negativos o contenido manipulado pueden producir JSON inválido o alterar la estructura enviada.

Recomendación: convertir a `decimal` con cultura explícita y serializar el objeto mediante una biblioteca JSON.

### Medio: configuración de plataforma de pruebas

La DLL productiva está configurada como `x86`, pero el proyecto de tests no fija esa plataforma. La ejecución default produce cuatro `BadImageFormatException` antes de ejecutar correctamente los tests.

La ejecución siguiente pasa los cuatro tests:

```text
dotnet test AlphaPOS.VposConnector.Tests\AlphaPOS.VposConnector.Tests.csproj --no-restore -p:PlatformTarget=x86
```

Recomendación: fijar `PlatformTarget=x86` también en el proyecto de tests y en CI.

### Medio: parsing JSON mediante expresiones regulares

`VposConnector.cs:351-399` interpreta respuestas JSON con expresiones regulares. No maneja de forma robusta escapes, comillas embebidas, estructuras anidadas ni todas las representaciones válidas de JSON.

Recomendación: usar `JavaScriptSerializer`, `DataContractJsonSerializer` o Newtonsoft.Json.

### Medio: errores HTTP tratados como respuestas normales

`HttpClientWrapper.cs:61-79` devuelve el body de una respuesta HTTP errónea sin conservar el código de estado. Un body inesperado que contenga `codRespuesta: "00"` podría clasificarse como aprobado aunque la respuesta HTTP sea un error del servidor.

Recomendación: devolver el estado HTTP junto con el body y separar errores de transporte del resultado transaccional.

### Medio: estado mutable no seguro para concurrencia

Las propiedades `Last*` se actualizan durante cada llamada. Compartir una instancia entre operaciones concurrentes puede mezclar el resultado, la solicitud y la respuesta de transacciones distintas.

Recomendación: serializar el uso de una instancia o crear una instancia por operación/hilo.

### Bajo: errores de logging silenciosos

`FileLogger.cs:31-41` descarta cualquier fallo de escritura. Una ruta inexistente, falta de permisos o bloqueo del archivo deja el diagnóstico sin evidencia.

Recomendación: garantizar la ruta, crear el directorio y disponer de un fallback observable.
